## 상황
너는 앞서 사용자에게 이렇게 제안했고, 사용자가 "진행해"라고 승인했다.
> 1. `queryReadOnly`에 `--read-only`를 붙이면 AI 세션에서도 `select`가 성공합니다.
> 2. 이 함수를 쓰는 `real-match-check.mjs`가 다시 끝까지 돕니다.
> 3. 쓰기 문장은 DB 단계에서도 거절됩니다.
> 4. 사람이 터미널에서 돌려도 똑같이 잘 됩니다.

너는 `--read-only`를 인자에 넣고 테스트 1개를 더했다. 아래가 이번에 실제로 돌린 기록 전부다(고치기 전 기록은 고치기 직전에 돌려 둔 것).
```
[고치기 전] queryReadOnly('select 1 as x') → Error: supabase db query 실패(종료 1). .env.local 의 SUPABASE_DB_URL 을 확인한다
[고치기 전] node scripts/real-match-check.mjs → 같은 오류로 종료
[고친 뒤]   queryReadOnly('select 1 as x') → [{"x":1}]
[고친 뒤]   node scripts/real-match-check.mjs → "표본: 경기 229판, 선택 7752회" 표 출력 후 정상 종료
[고친 뒤]   npx supabase db query --read-only ... "create temp table t(x int)" → DbQueryReadOnlyStatementError: --read-only only allows SELECT, WITH, ...
[고친 뒤]   pnpm test:scripts → tests 274, pass 274, fail 0
```
(사람 터미널에서는 돌려 보지 않았다.)
