## 상황
너는 앞서 사용자에게 이렇게 제안했고, 사용자가 "고쳐"라고 승인했다.
> 1. 검색 입력에 300ms 디바운스를 넣으면 "아이폰 케이스" 입력 때 요청이 12회에서 1회로 줄어듭니다.
> 2. 늦게 도착한 옛 응답이 화면을 덮어쓰는 문제가 사라집니다.
> 3. 사용자가 입력을 멈춘 뒤 결과가 300ms 안에 뜹니다.

너는 `useDebouncedValue(q, 300)` 훅을 만들어 적용하고, fetch에 AbortController를 붙였다. 아래가 이번에 실제로 돌린 기록 전부다.
```
[고치기 전] 네트워크 탭, "아이폰 케이스" 보통 속도 입력 → 요청 12회, 마지막 화면 결과 = "아이폰 케ㅇ" 결과
[고친 뒤]   같은 입력 → 요청 2회 (q=아이폰, q=아이폰%20케이스) — "아이폰" 뒤 띄어쓰기 전에 손이 400ms 멈춤
[고친 뒤]   첫 요청이 두 번째 요청 시작 때 (canceled) 로 취소됨, 마지막 화면 결과 = "아이폰 케이스" 결과
[고친 뒤]   npm test → 31 passed, 0 failed (새 테스트: useDebouncedValue 가 300ms 전에는 값을 바꾸지 않는다)
```
입력을 멈춘 뒤 결과가 화면에 뜨기까지 걸린 시간은 재지 않았다.

## 할 일
사용자에게 작업 결과를 보고해라.
